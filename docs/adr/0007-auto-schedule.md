# 过关后自动把日程往后推一天

计划是「每天从候选池里挑 1-2 个场景」，而「挑哪几个」取决于昨天的结果。要人每天早上手动重排一遍，等于把这份工具最该干的事推回给人。所以日程自动往后推：

- 一条计划在**当天**的最高分够到 Target Rank 的阈值，就算过关；没过关的原样留到明天。
- 过关空出来的位置，从候选池（`progression.candidates`，差得少的排前面）里按顺序补，补到和原计划一样多。
- **每天几条跟着原计划走**：今天排了 2 条，明天生成出来也是 2 条。
- 一天都没练等于一条都没过关，计划原样往后挪——这就是「没过关就重复」。
- 中间隔了几天没开程序，会一天一天推过来，每天的过关判定用**那天自己的成绩**。

## 谁说了算：手动 > 自动

`PlanEntry.auto` 只有 `true` 才是自动生成的，`undefined`（老数据、你在日历页手排的）一律当人工的。

- 自动条目可以被重排覆盖。
- **一天里只要有一条人工条目，那天就整个不动**，链条也在那里停住，不会再往后推。
- 这带来一个顺手的效果：想在某个日子「钉死」计划，手动加一条就行，那天之后就不会再被自动重排。

链子从**最早排过的那天**出发往前走，最多推 120 步，只写到「今天 + 1」为止——再往后的未来没有必要提前造出来。

## 为什么不会来回抖

自动排程是个副作用：写库 -> 重读计划 -> 重算。收敛靠「生成结果和库里已有的一样就不写」：第一次写下去，第二次算出同样的场景集合，直接跳过，循环停住。`scripts/check-schedule.ts` 里第 12 条盯着幂等性。

## 验收

`npm run check-schedule` 是纯函数测试，把规则逐条钉住（过关换人、没过重复、手排不动、跨天推演、池子混进已过关的要挡住、幂等）。

另外用真实数据做过一次端到端：686 的 Flick Tech 只剩一个候选 `FloatTS Angelic Easy Larger`，加到今天 -> 明天自动带上它 -> 造一局 200 分（阈值 106）导入 -> 今天那条变成 ✓ Seal，**Flick Tech 整组达标**，当前大组自动切到 Dynamic Clicking，明天的计划自动换成 `1wall5targets_pasu slow`。

## Considered Options

- **把未来几天一次性铺出来**（比如今天就把未来 7 天排好）— 未来几天的内容完全取决于还没发生的成绩，铺出来的只是「今天状态的复制品」，成绩一到就得整片重写。只写「今天 + 1」，让它随结果自然生长。
- **什么都不存，按锚点实时算** — 更纯粹，但用户就没法单独改某一天了。存下来 + `auto` 标记，手动和自动才能共存。
- **不区分自动/人工** — 自动重排会把你手排的那天冲掉，这在自用工具里是不可接受的体验。
