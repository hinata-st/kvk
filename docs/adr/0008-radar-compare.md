# 大组对比画雷达，不画曲线

主页原来那张「所有大组对比」是每个大组一条累积 PB 曲线，Y 轴是「历史最高分 ÷ 该场景最高等级阈值」再对组内场景取平均。三个问题：

- 同一个 benchmark 里各组水平本来就接近，几条线挤在同一条高度带上，谁高谁低得盯着看。
- 想回答的是「我现在练的这个组排第几」，可曲线擅长的是趋势，位置反而被压扁。
- 分数尺度不同，只能换算成百分比，可那个百分比在每根轴上的含义都不一样。

## 决定

换成雷达：每根轴是一个大组，轴上的值是 **段位进度**（`rankProgress`：整数部分是已达段位，小数部分是往下一段位走的比例），半径上限就是这张 benchmark 的段位数。

段位是同一个 Benchmark 里唯一共同的尺子。分数换算成百分比也一样是「除以各自的阈值」，除完还是没法横向比。

## 细节

- 层级可以切 大组 / 子类别 / 场景。后两级只画**当前大组**：整张 benchmark 摊开是一二十根轴，挤在一张雷达上什么都读不出来。全部达标（没有当前大组）时退回整张表。
- 环画在整数段位上，环上的段位名用 HTML 叠在图上。ECharts 的 `radar.axisLabel` 会在**每根轴**上重复一遍，14 根轴就是一团糊，所以没用它。
- 绿色多边形是当前进度，橙色虚线是目标等级——一根等半径的多边形，看起来就是个圈。
- 没打过的场景按 0 算，它确实是你还没拿到的部分。
- 列表右边那个百分比是**曲线首尾变化**（stats 目录里第一天到最近一天的当日最高分），不是段位进度。两个数各说各的事，所以文案里分开写。
- 颜色按分组走：大组层级按大组上色，子类别和场景层级按子类别上色——不然一屏全是同一个色。

## 代价

丢掉了「只涨不跌的累积 PB 曲线」这条时间线。单个场景的曲线没丢（场景详情页和主页的小图都在），丢的是「所有大组放在同一张时间轴上」这个视图。原本靠它看的是各组增长速度，现在雷达看的是当前高下。

## 验收

`npm run check-radar`：段位进度、首尾变化、三个层级的轴、当前大组的收窄规则、全部达标后的退路。
