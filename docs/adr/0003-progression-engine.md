# 训练推进引擎：用户挑项目，分数单独决定推进

每日训练计划由**用户手动挑选**，系统不自动生成。用户每天从「候选池」里挑 1-2 个 Scenario 作为当天条目。

推进单位是 Category。候选池 = 当前 Category 中所有尚未达到 Target Rank 的 Scenario，按「离达标差几级」升序排列。系统只负责算池子和排序，选哪个由用户决定。

当天存在两个彼此独立的闸门：

- **Quota 闸门** — 当天所有 Run 的合计局数，只驱动当天的进度显示。
- **Target Rank 闸门** — 决定推进。某个 Scenario 当天的最高分达到 Target Rank 阈值即为过关，与 Quota 是否练满**无关**。

当 Category 内所有 Subcategory 都达标，才切换到下一个 Category。

## Considered Options

- **系统自动取排序前 N 个当今日计划** — 被否决。用户明确要自己挑，理由是同类别里未达标的项目常有 5-8 个，今天先练哪个跟手感和弱项判断有关。
- **Quota 未练满则不推进** — 被否决。训练量是自律指标，等级是能力指标。打到过关分就说明这个项目已经拿下，硬要重复一天是浪费。

## Consequences

- 曲线图的 Y 轴与推进判定共用同一套段位刻度，但因为 ADR-0002 的 100 倍单位差异，两处必须用同一份归一化逻辑。
- 用户可能连续多天练同一个 Scenario（一直没过关），历史里会出现长尾，UI 要能容忍。
