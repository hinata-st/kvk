# benchmark 目录只当名字和分组的来源，结构仍以官方为准

官方 API 对任意 benchmarkId 都返回完整结构，但**不返回名字**（见 ADR-0004）。只有 ID 的列表没法挑：614 个 benchmark 全显示成 `#2337 · 36 个场景`。

evxl.app 把社区 benchmark 的名字和「大组 → 子类别」的整理结果硬编码在前端 chunk 里。`npm run catalog` 把它抽成 `public/benchmark-catalog.json`（129 个 benchmark、263 个难度、109 KB）。

## 覆盖层的三条规矩

1. **结构永远以官方 API 为准。** 子类别有哪些、每个子类别有哪些场景、段位阈值是多少，都来自官方。目录只提供名字和分组。
2. **官方子类别名是身份，目录名只是显示。** 同一份数据里两者会不一样（官方 `Speed Track` vs 目录 `Speed`），而官方名在同一个 benchmark 内唯一，所以 IndexedDB 里的分组表、计划条目一律存官方名，界面渲染时再换成目录名。
3. **对不上就不猜。** 官方的 `categories` 层级**不统一**：Viscose 那套里它就是叶子（`Arm`、`Wrist`…），Voltaic S5 那套里它是顶层（`Clicking`、`Tracking`、`Switching`），叶子在下一级。所以只认两种精确对齐——展平后逐项相等（借名字 + 借分组），或顶层逐项相等（只借名字）。实测 263 个难度里 240 个带分组、167 个能精确对齐；对不上的（PureG S1 目录 7 组 vs 官方 8 组，Aimerz+ 目录里子类别名是空的）就当没有名字，退回「编号 + 规模」，分组由用户在设置页自己填。

## 代价与后果

**空名字的分组不算分组。** 目录里有 56 个 benchmark（如 `Underaim Benchmark` 2942、`Run and Gun Valorant` 675）顶层分组名是空字符串——它们的编排本来就只有一层。把空名字当大组名用，整个 benchmark 会缩成一个没名字的组：推进没有可切的目标，界面上一整条侧边栏全被高亮，反而看不出在练哪一块。所以 `buildGroups` 直接跳过空名分组，它的子类别按下面的兜底规则各自成组，这样左侧栏才有 Smooth / Micro adjust / Corrections 这些能一眼分辨的组。

- 目录是**别人的整理结果**，会过时、会有错。所有从它来的东西都是可选的、可覆盖的：名字对不上就是编号，分组对不上就是各自成组，用户手改的分组永远优先（`groupingDraft ?? 目录 ?? 种子`）。
- 拉取依赖 evxl 的部署，chunk 名带 hash。脚本不写死路径，从首页的 modulepreload 列表里逐个找；找不到就报错退出，**不覆盖旧文件**。
- 官方没有列表接口这件事没变（见 ADR-0004），所以有人新设计了一个 benchmark，还是得靠 ID 现拉。
