# 分数单位：本地 stats 与官方 API 相差 100 倍

KovaaK's 写在本地的 stats CSV 里，`Score` 是游戏内显示的值（例如 `139.300003`，带 float32 精度尾巴）。而官方 `player-progress-rank-benchmark` 接口返回的 `score` 是同一个值的 **100 倍**（`13930`）——后端按两位定点数存储。

但**同一个接口**返回的 `rank_maxes`（各段位的分数阈值）用的是**本地那一套单位**（例如 `[65, 78, 90, 100, 110, 120, 130, 142]`）。

因此：判定过关时，必须拿**本地分数**去比 `rank_maxes`，或者把 API 的 `score` **除以 100** 之后再比。直接比较不会报错，只会让所有段位判定静默偏大 100 倍。

## 判定规则

分数 ≥ `rank_maxes[i]` 时，段位 = `i + 1`（从 0 开始数阈值）。用 `beanTS Larger` 验证：本地 139.30，第 7 个阈值 130、第 8 个阈值 142，139.30 落在区间内 → 段位 7，与官方返回的 `scenario_rank` 一致。8 个场景交叉验证全部吻合。

## Consequences

- 解析本地 CSV 时必须保留两位小数，不能取整，否则会踩到阈值边界。
- 本地 CSV 的浮点尾巴（`139.300003`）要在解析时四舍五入到两位。
- 界面上一律显示**本地单位**的分数（玩家在游戏里看到的就是这个）。
